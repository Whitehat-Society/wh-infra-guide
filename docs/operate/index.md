# Run the event: overview

## The goal

During the event, three things matter. Players should be able to reach the scoreboard and every challenge, you should hear about a problem within minutes, and no team should lose a solve. When the event ends, the club needs the final results before the system is deleted.

## The order

The pages in this section follow the event from start to finish. The first one is a routine you keep running all day, the next four are for when something needs to change, and the last two are what you do once the event is over.

| When | Page | What it gives you |
|---|---|---|
| All day | [Watching the system](monitoring.md) | What to keep on screen, what each alert means, and what to do when one fires. |
| When challenges are slow | [Adding capacity](scaling.md) | More copies of a program, or more computers to run them on. |
| When a challenge needs fixing | [Change a challenge](change.md) | The steps for each kind of change, such as new text, a new flag or new server code. |
| When an old version won't go away | [Where data is kept](data.md) | Every place a copy is kept, and how to clear each one. |
| When data is lost | [Backup and restore](backups.md) | How to put the database back from the hourly backup. |
| When the event ends | [Collect the results](results.md) | The final scoreboard, the spreadsheets and the statistics. |
| Before the next event | [Known weak spots](risks.md) | The problems found after WH-2026, ranked, with how to fix each one. |

Before the event starts, run [Final checks](../deploy/verify.md) once more on the morning of the event.
