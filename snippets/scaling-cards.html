Node level · Cluster Autoscaler 9.46.2

Adds nodes when pods can't be scheduled

  • Node group bounds: min 2, max 6 by default (the audit records max 8 in the deploy-time tfvars).
  • New node allowed up to 5m to join.
  • Removes a node after it has run below 50% of requested capacity for 10m, and not sooner than 10m after a scale-up.
What triggers it

Pending pods, not CPU load

The autoscaler reacts to pods that don't fit, judged by their requests. A traffic spike makes existing pods busier but creates no new pods, so it never adds a node. Extra capacity only arrives after someone raises a replica count.

Pod level

Fixed replicas

Web 2 × 5, pwn 3 × 5, ingress 2, CTFd / MariaDB / Redis 1 each. Pods are not CPU-capped at the request: each challenge pod requests 100m but may burst to 500m, so pods on the same node compete for spare CPU.
