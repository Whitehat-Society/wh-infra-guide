1. CTFd, MariaDB and Redis are one pod each, on single-AZ EBS volumes.If that node or AZ is lost, the whole event stops until a pod reschedules in the same AZ. The fix is managed RDS + ElastiCache, plus uploads on S3 so CTFd can run more than one replica.
  2. Rate limits probably key on NLB addresses, not players.Turn on proxy protocol (NLB annotation plus use-proxy-protocol in NGINX), or set externalTrafficPolicy: Local with client-IP preservation, then re-test the limits.
  3. Web replicas hold their own state.Either keep stateful challenges at 1 replica, add sticky sessions (nginx.ingress.kubernetes.io/affinity: cookie), or pin secrets and move state out of the pod.
  4. No pod autoscaling.Add metrics-server + HPA for the stateless challenges and the ingress. The node autoscaler then has pending pods to react to.
  5. One NAT gateway.Losing its AZ cuts outbound traffic (image pulls, ACME, the S3 backup path) for nodes in all 3 AZs.
